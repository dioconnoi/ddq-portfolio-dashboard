# Free-tier verification

Checked on **2026-09-24** against vendor documentation (primary sources unless noted).
Purpose: confirm the free-tier facts that `docs/PLAN.md` §12 and decisions D2–D4 rest on.

**Overall verdict:** no decision is invalidated. Two facts were refined (Render RAM is ~500 MB, and Brevo's exact sender-verification flow is not documented on its pricing page). Both are re-checked at the point of use.

| # | Claim | Verdict | What the source says | Source | Impact on plan |
|---|-------|---------|---------------------|--------|----------------|
| 1a | Render free web services sleep when idle and restart slowly | Confirmed | Spin down after 15 minutes without inbound traffic; about one minute to restart. 750 free instance hours per workspace per month. | https://render.com/docs/free | Cold-start UX in the SPA stays; keep-warm ping every 10 min uses ~720 of 750 h, which fits a single service. |
| 1b | Render free has no cron jobs or background workers | Confirmed | Cron jobs and background workers "don't support Free instances". Also: single instance, no persistent disk, local filesystem lost on redeploy or spin-down, free Postgres expires after 30 days (we use Supabase). | https://render.com/docs/free | D3 (Postgres queue ticked by GitHub Actions) stands. |
| 1c | Render free RAM is 512 MB | Refined | The docs page gives no figure; Render's forum/compute docs indicate about 500 MB. | https://render.com/docs/free ; https://community.render.com/t/clarification-on-free-tier-instance-ram-allocation/26734 | Design budget stays "under ~500 MB". Bound Monte Carlo/optimizer sizes (D8 unchanged). Measure real memory in Phase 0 go-live. |
| 1d | Blueprint supports `autoDeployTrigger: checksPass`, `sync: false` env vars | Confirmed | Both documented; `preDeployCommand` exists and the page does not restrict it to paid plans, but free-tier availability is not stated. | https://render.com/docs/blueprint-spec | Migrations still run from CI (`migrate` job), not from `preDeployCommand`, so the unclear point does not matter. |
| 1e | Render native Python version selection | Confirmed | `PYTHON_VERSION` (fully qualified) beats `.python-version` (patch may be omitted); services created on/after 2026-02-11 default to 3.14.3. | https://render.com/docs/python-version | We pin 3.12 explicitly (`PYTHON_VERSION=3.12.10` in `render.yaml`, `.python-version` = `3.12`). Without the pin Render would pick 3.14. |
| 2 | Fly.io has no free tier for new accounts | Confirmed | New accounts get a trial of "2 hours of machine runtime or 7 days of access, whichever comes first"; no permanently free allowance is documented. | https://docs.fly.io/about/free-trial/ | D2 (Render) stands. |
| 3a | Supabase free: 500 MB DB, pauses after inactivity | Confirmed | 500 MB database, 50,000 MAU, 2 active free projects, "Free projects are paused after 1 week of inactivity". | https://supabase.com/pricing | Keep-warm ping also touches the DB so the project does not pause. |
| 3b | Supabase direct connection is IPv6-only; poolers are IPv4 | Confirmed | Direct: IPv6 only on Free. Session pooler (port 5432) and transaction pooler (6543): IPv4. "Transaction mode does not support prepared statements." Session pooler recommended for IPv4-only networks such as GitHub Actions. | https://supabase.com/docs/guides/database/connecting-to-postgres | Migrations use the session pooler; runtime uses the transaction pooler with prepared statements disabled (as planned). |
| 4a | Brevo free tier daily cap | Confirmed (secondary) | 300 emails/day shared between marketing and transactional, free forever. The vendor pricing page did not display the number; figure taken from third-party reviews. | https://www.brevo.com/pricing/ ; https://www.brevo.com/products/transactional-email/ | Enough for owner-only alert emails. Exact sender-verification steps (single sender vs domain) get re-checked in Phase 7 before building the adapter. |
| 4b | Resend cannot email third parties without a verified domain | Confirmed (secondary) | Until a domain is verified, mail can only go from `onboarding@resend.dev` to the account owner's own address. Free plan: 3,000/month, 100/day. | https://resend.com/pricing ; https://resend.com/docs/dashboard/domains/introduction | D4 (Brevo behind an `EmailSender` port) stands; Resend is a one-adapter swap if the user gets a domain. |
| 5 | GitHub disables idle-repo schedules after 60 days | Confirmed | "In a public repository, scheduled workflows are automatically disabled when no repository activity has occurred in 60 days." Minimum interval 5 minutes; runs may be delayed at high load (start of every hour). | https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows | Keep-warm cron is best-effort; documented fallback is an external pinger. |
| 6 | Vercel Hobby is non-commercial | Confirmed | "the Hobby plan restricts users to non-commercial, personal use only." Includes 100 deployments/day. | https://vercel.com/docs/plans/hobby | A personal portfolio qualifies. |
| 7 | yfinance is unofficial and Yahoo-terms-bound | Confirmed | README: not affiliated with Yahoo; "the Yahoo! finance API is intended for personal use only". Latest release/rate-limit notes were not visible on the README page. | https://github.com/ranaroussi/yfinance | Keep the cache + stale-while-error + fallback design, show source attribution, and do not commit Yahoo data to the repo (already in PLAN §5). Re-check release status at the start of Phase 1. |
